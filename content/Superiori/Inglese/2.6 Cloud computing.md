### Cloud Computing
Hint: def (+ pay model + datacenters), characteristics (OBRRM)
::
Is the **on-demand availability & delivery of resources** (computing, storage capacity…) **as services** to end users. Cloud computing **shares resources** on-demand using a **pay-as-you-go model**. Large clouds often distribute functions over multiple locations, called **datacenters**.
##### Characteristics
- **On-demand self-service**: resources are <u>required automatically</u> when needed without human interaction,
- **Broad network access**: resources are <u>available over internet</u> and accessed through client platforms,
- **Resource pooling**: the provider’s <u>resources are pooled</u> to serve multiple consumers (dynamically assigned to each),
- **Rapid elasticity**: capabilities are <u>elastically provided and released</u> (sometimes automatically).
- **Measured service**: cloud systems <u>auto control/optimize resource use</u> by <u>measuring/monitoring user’s activity</u>.

### Models

##### IaaS
Hint: def, what client manages? (+ why)
::
Refers to **physical/virtual machines** (run as guests by the hypervisor) offered **on-demand** (so > capabilities + < invest on hw).
Clients are able to deploy & run sw (like OS and apps). The client <u>doesn’t manage the cloud infrastructure</u>, but **controls**:
- OS,
- Storage,
- Deployed applications,
- (Maybe limited control of networking components like firewalls…)
###### Why use IaaS?
So, you **won't have to buy & manage** the **hw**.
<!--SR:!2024-05-30,7,220-->

##### PaaS
Hint: def, what client manages?
::
Refers to a pc **platform** including: **OS**, programming **environment**, **db** & **web server**. With this devs can deploy and run sw on a cloud platform without having to buy & manage the underlying hw & sw.
The client <u>doesn’t manage the cloud infrastructure + network, servers, OS or storage</u>, but **controls**:
- Deployed applications,
- Data,
- (Maybe configuration settings for the application-hosting environment).
<!--SR:!2024-05-28,5,220-->

##### SaaS
Hint: def, what client manages?
::
Apps are installed & running **in the cloud**, and are accessible from various client devices through a browser.
The client <u>doesn’t manage the cloud infrastructure or the platform</u> (network, servers, OS, storage…), but **controls**:
- The used application (not its capabilities, but its **results**/**outputs**),
- (Maybe limited user-specific configuration settings).
With SaaS the client <u>doesn’t need to install the app</u>; and SaaS is often referred as on-demand service and usually priced on a <u>pay-per-use basis or with a subscription fee</u>.

### Types

##### Public Cloud Computing
Hint: def (+ why public, free/paid, security), advantages (4, LNNH)
::
A **multi-tenant environment** in which <u>servers share the same resources as others cloud tenants</u> (usually *pay-as-you-go*).
Cloud services are “**public**” when <u>delivered over the public internet</u> & can be **free** or **paid** (with subscription); but, respect to the private cloud, here **security concerns** increase as <u>services are shared</u> by multiple "<u>tenants</u>" and <u>everything</u> (sw and hw) is <u>controlled by the cloud provider</u>.
###### Advantages
- **Low costs**: no need to buy hw or sw, you pay only for the service that you use,
- **No maintenance**: service providers provide maintenance,
- **Near unlimited scalability**: on-demand resources are available to meet your business needs,
- **High reliability**: vast network of services ensures against failures.
<!--SR:!2024-05-30,7,220-->

##### Private Cloud Computing
Hint: def, characteristics (3), advantages (3, FCS)
::
Is a **single-tenant environment** that:
- Is dedicated to a **single client**/company (so it’s customizable & maintained on a private network),
- Is hosted & managed **internally** (on-site) or by an **external** 3rd-party (outsourced),
- (Hw is dedicated, so client always pays a fixed amount).
Private clouds are often used by government agencies, financial institutions or other companies which need enhanced control over their environment.
###### Advantages
- More **flexibility**: the organization can customize its cloud environment,
- More **control**: higher privacy, because resources are not shared (outside of the company),
- More **scalability**: more scalability than on-premise (in sede) infrastructures.

##### Hybrid Cloud Computing
Hint: def, benefits (intro + overflows), advantages (4, CFCE)
::
Cloud that combines **on-premise infrastructure** with a **public cloud**; allowing data sharing between the 2.
###### Benefits
Hybrid cloud **benefits**: > flexibility, > deployment options, security, compliance, > value from existing infrastructure.
In case of **overflows** (too much info), hybrid cloud **seamlessly scales up** the <u>on-premises</u> infrastructure with the <u>public cloud</u>; so companies can run certain workloads in the cloud while keeping sensitive data in their datacenter.
###### Advantages
- **Control**: org can maintain a private infrastructure for sensitive data & workloads that need low latency,
- **Flexibility**: additional resources in the public cloud can be used when needed,
- **Cost-effectiveness**: since public cloud can be scaled up, only the needed extra computing power is paid,
- **Ease**: the migration isn’t overwhelming because it can be done gradually over time.

#### Public, Private or Hybrid?
There's no one type of cloud computing that's right for everyone. Different cloud computing models, types and services have evolved to meet the rapidly changing tech needs of orgs.
